## Executive summary

A case-insensitive text scan of the current working tree found **1,909 matching lines in 121 readable text files**. A separate scan of tracked `HEAD` found **1,969 matching lines in 182 tracked files**, including screen/design files that are currently deleted from the working tree. The current checkout already contains many unrelated modified, deleted, and untracked files; this report does not restore, stage, or otherwise alter them.

Most visible brand copy, comments, asset filenames, and internal Swift symbols are **safe to rename in a coordinated source change**: they do not themselves identify an installed app or external account. The app bundle ID and StoreKit product IDs are **high-risk external identifiers**. Changing the app bundle ID is not a normal update/rename for installed users; changing subscription product IDs does not rename existing App Store products or historical transactions. Notification request IDs have a local persistence/cancellation dependency. Domain, email, App Store, build-target, and asset-catalog references require their own coordinated updates.

The working tree contains no declared custom URL scheme, Universal Link association, App Group, keychain access group, or non-empty entitlement. `Info.plist` has no `CFBundleURLTypes`; `Pencild.entitlements` contains only an empty dictionary and explanatory comment. No Keychain API use or App Group entitlement was found in `Sources`, `Tests`, `project.yml`, the generated project, or the entitlements file. This negative finding is limited to the searched repository content; it does not establish what may exist in Apple Developer or App Store Connect accounts.

## Classification key

- **SAFE — copy/resource:** User-visible name, prose, comments, or an asset filename. Rename/update references together; no app-data migration is implied by the string alone.
- **SAFE WITH BUILD COORDINATION — internal code/project name:** Swift symbols, module/target/scheme names, and paths. These can be renamed, but every importer, generated-project input, CI command, script, and documentation reference must remain consistent.
- **RISKY — external or durable identifier:** App bundle identifier, StoreKit product ID, website/email endpoint, notification request/category identifier, or a value written into persisted records. Preserve compatibility or provide a deliberate migration/parallel-support plan.
- **ABSENT — checked, not found:** No corresponding repository implementation/registration found in the inspected files. Do not infer external account state.

**Bundle-ID migration implications:** The current app has a single app bundle ID configured in the app target and shared base xcconfig, plus a separate test bundle ID. Apple platform identity, code-signing/provisioning, App Store Connect app record, entitlements/capabilities, receipt/environment behavior, and app data are tied to the app ID. A build with a different bundle ID is generally a separate installed app and sandbox, not an in-place update of this installation. Standard `UserDefaults` and the implicit SwiftData store are app-container scoped; the current app’s persisted model container is installed from [`Pencild.swift`](../../Sources/Pencild/Pencild.swift#L8-L18). A bundle change therefore risks making existing local scans, records, preferences, and app-container data appear absent. Do not promise automatic migration based on this source inspection. Before any ID change, determine whether the current app ID has been registered, whether a production app record/build exists, and what Apple’s applicable transfer/rename constraints are. If retaining the current app is required, prefer keeping its bundle ID and changing the display name; if a new ID is unavoidable, plan a separate-app transition and user-visible data/subscription expectations.

Update the local StoreKit configuration and tests to reflect both generations. The repository does **not** prove that the named group/products have been created in the live Apple account; [`HANDOFF.md`](../../HANDOFF.md#L42-L61) still presents registration and creation as checklist items.

The StoreKit **display names** are **SAFE — copy/resource** in the local configuration, though live localized product/group display text must be checked independently.
