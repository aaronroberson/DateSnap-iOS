# DateSnap native app — implementation behavior audit

**Audit date:** 2026-10-09<br>
**Scope:** The existing native iOS app implementation in `Sources/DateSnap/`, its app configuration/resources, and `Tests/DateSnapTests/`. This is an implementation inventory, not a design proposal, security certification, store listing review, or live-device test. References below link to source files and approximate line spans in the audited checkout.

## Executive summary

DateSnap is a SwiftUI iOS application with four primary tabs: **Home**, **Review**, **History**, and **Settings**. It imports photos/screenshots and (for Premium) one PDF or image file, performs Vision OCR on-device, creates deterministic event interpretations with an optional capability-gated Apple Intelligence pass, persists scan/event/review data in SwiftData, and only writes to Calendar/Reminders/local notifications after an explicit event-save action. The event review screen exposes extraction uncertainty, field provenance, alternatives, OCR evidence and editable fields. Single scans with multiple results open the first event for review and leave the rest in Review; batch scans open a combined review sheet.

The implementation also includes lifecycle/archive tools, StoreKit 2 Plus/Premium subscription surfaces, a privacy/data-control screen, local notification deep links and DEBUG-only screen/interpretation tools. There are 19 Swift test files with 114 `@Test` declarations (as counted at audit time), mostly testing pure logic and service/view-model paths; no UI-test target/files were found. A live device run, actual permission prompts, real StoreKit transactions, notification delivery, and production Apple Intelligence availability are **not established by this source audit**.

## 1. App structure and navigation

- The app entry point constructs a live `ServiceContainer`, injects it into `ContentView`, and installs a SwiftData model container for `UserSettings`, `ScannedAsset`, `EventCandidate`, `SavedEvent`, and `InterpretationRecord` ([DateSnap.swift](../../Sources/DateSnap/DateSnap.swift#L4-L19)).
- `ContentView` owns the app/session view models and selects one of four root tabs. It renders a custom tab bar and toast, presents app modals and batch review as sheets, opens notification deep links, and refreshes permission status and StoreKit entitlements when the scene becomes active ([ContentView.swift](../../Sources/DateSnap/ContentView.swift#L4-L117), [AppState.swift](../../Sources/DateSnap/Models/AppState.swift#L20-L65)).
- `SettingsClusterView` is a `NavigationStack` with routes to Manage Plan, Privacy Center, Enhanced Interpretation, Reminder Preview, Help & Feedback, and—DEBUG only—Marketing Kit. `SettingsState.pendingRoute` supports programmatic routes from the gallery/help surface ([SettingsClusterView.swift](../../Sources/DateSnap/Views/SettingsClusterView.swift#L4-L44), [SettingsState.swift](../../Sources/DateSnap/Models/SettingsState.swift#L1-L7)).
- Other root content and major screens use nested `NavigationView`s and app-wide sheets rather than a single typed navigation graph. `AppModalScreen` enumerates paywalls, permission states, no-dates, event detail/review, alert editor, recent screenshots and screen gallery ([AppState.swift](../../Sources/DateSnap/Models/AppState.swift#L38-L64)).

## 2. Per-screen actions, states, validation and edge cases

### Home / scanner

**Actions:** scan recent screenshots; open the Photos picker for one or multiple images; import a PDF or image from Files; try a programmatically rendered sample flyer. The sample path requires no Photos permission. File import checks the Premium entitlement at the scan operation boundary. The picker itself uses `.images`; File importer accepts PDF/image and only one URL ([HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L288-L425), [HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L480-L550), [ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L99-L149)).

**States and edge cases:** scan progress distinguishes loading, OCR, extraction and model interpretation; interpretation can be cancelled to use the rules result. Failed loads/errors toast. Recent-screen access requests Photo Library read/write access when undetermined; denial offers Open Settings, Choose a Photo Instead, or Cancel. Limited/authorized library states are handled separately in the screenshot picker ([ScanFlowViews.swift](../../Sources/DateSnap/Views/ScanFlowViews.swift#L44-L96), [HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L489-L506), [HomeViewModel.swift](../../Sources/DateSnap/ViewModels/HomeViewModel.swift#L68-L89)).

Plus has a Home card when screenshots are available/authorized. It shows at most eight visible unscanned images; Plus triage assesses a bounded set on-device. The implementation observes Photos-library changes and reloads recent screenshots, then may triage likely events, but **source inspection does not establish background execution, automatic OCR scan-to-review for every new screenshot, or an automatic notification prompt** ([HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L555-L630), [HomeViewModel.swift](../../Sources/DateSnap/ViewModels/HomeViewModel.swift#L134-L181), [PhotoCandidateRanker.swift](../../Sources/DateSnap/Services/PhotoCandidateRanker.swift#L1-L35)). The Home marketing card’s “automatic detection” language should therefore be read against that code boundary rather than as proof of a background service.

The Plus card’s nearby copy says “watches” and “checks new ones” but the explicit scan action remains a user tap on a displayed asset. The imported document path processes up to 30 PDF pages (not an unbounded document) and does not establish multi-file batch import; the Photos picker does support selecting multiple images ([ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L106-L149), [HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L489-L500)).

### Single scan and scan-result routing

`ScanViewModel` stages are idle, fetching, OCR, extraction, interpretation, complete candidates, no dates, already saved, and failure. It fetches Photos images at a bounded target size, accepts direct `UIImage`/data/sample inputs, and funnels pages through OCR, interpretation and persistence. PDF pages are rendered and processed in order; individual pages with no OCR text are skipped; a single-page OCR error fails the scan ([ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L9-L64), [ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L68-L163)).

When a scan yields candidates, the app stores the source image in in-memory `AppState`, opens only the first candidate in Event Review, and toasts the count waiting in Review. If all matching candidates already have saved records, it sends the user to History. No-dates routes with OCR text/image; failures clear the active modal and toast ([ScanFlowViews.swift](../../Sources/DateSnap/Views/ScanFlowViews.swift#L17-L41)).

### Recent screenshots

The grid loads up to 30 recent screenshot-album assets. A normal tap scans one; Select mode toggles image IDs and Scan Batch submits them in selection order. Cancel leaves selection mode; Close dismisses. Empty state differentiates limited access from no screenshots, and already-scanned IDs display a badge ([ScanFlowViews.swift](../../Sources/DateSnap/Views/ScanFlowViews.swift#L99-L203), [ScanFlowViews.swift](../../Sources/DateSnap/Views/ScanFlowViews.swift#L222-L287)). A failed photo fetch is represented per batch item, not as a global batch failure.

### Review queue

Shows candidate records that have never been committed or are `.draft`. Each row uses candidate confidence tier, date and time; tapping opens review. The empty state offers Go to Scanner. The data query sorts newest candidates first; no explicit delete/archive actions are shown on this screen ([ScanFlowViews.swift](../../Sources/DateSnap/Views/ScanFlowViews.swift#L364-L461)).

### Event Review / Edit

**Actions:** edit title, start/end and all-day mode, venue/address, optional RSVP URL and notes; inspect/hide original image; expand raw OCR; choose writable calendar and reminder list; configure up to three alert offsets; answer ambiguity questions; choose an alternate interpretation; inspect “Why this?” evidence; inspect duplicate matches and open/keep-separate; view extracted flyer actions, open validated links, and optionally accept a Premium RSVP-deadline reminder. The screen then offers Save Event to Calendar, Save Draft, and Discard (for unsaved items) ([EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L68-L150), [EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L278-L404), [EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L405-L769), [EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L770-L862)).

**Validation and uncertainty:** an empty/whitespace-only title becomes “Untitled Event” on apply; timed end dates are clamped not earlier than start; all-day candidates store no end date. A numeric ambiguous date can be swapped only when the old day fits a month (day ≤ 12); user can explicitly keep the parsed order. Inferred year is called out. Reminder offsets are unique and capped at three. Link actions permit only `http`, `https`, `tel`, and `mailto` according to action type ([EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L131-L155), [EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L206-L235), [InterpretationReviewViews.swift](../../Sources/DateSnap/Views/InterpretationReviewViews.swift#L253-L347)).

On appearance it looks for duplicate candidates and calls `prepareDestinations`; if Calendar or Reminders authorization is undetermined, this may request access as the review opens, before the user taps Save. A missing candidate displays “This event is no longer available.” Calendar denial returns failure and routes to Calendar recovery. Calendar success followed by Reminder, local notification, deadline-reminder, or SwiftData issues may return partial or persistence failure; notification-denial state uses human-readable guidance and the screen toast can say local alerts are off ([EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L126-L145), [EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L184-L204), [EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L315-L476)). A draft persists locally without Calendar/Reminders writes; discard only deletes a candidate that has no saved-event record ([EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L259-L313)).

### Interpretation review components

The pipeline starts with deterministic extraction/evidence/quality, chooses optional on-device interpretation only if the user toggle, rollout, runtime capability, scan-worthiness and semantic-trigger policy all allow it, then validates/ranks model hypotheses. The model is optional and failure/timeout/invalid output falls back to rule output; configured limits are 60 OCR lines, 3,000 characters and a 20-second timeout ([EventUnderstandingPipeline.swift](../../Sources/DateSnap/Services/Intelligence/EventUnderstandingPipeline.swift#L1-L185), [IntelligencePolicy.swift](../../Sources/DateSnap/Services/Intelligence/IntelligencePolicy.swift#L1-L58)). Runtime Foundation Models availability is gated to iOS 26+ and checked dynamically ([IntelligenceComposition.swift](../../Sources/DateSnap/Services/Intelligence/IntelligenceComposition.swift#L1-L28), [IntelligenceCapabilities.swift](../../Sources/DateSnap/Services/Intelligence/IntelligenceCapabilities.swift#L1-L66)).

Review UI identifies rules/model routes, field provenance and “please check” cases, presents unanswered material questions and alternatives, and keeps model selections editable rather than auto-saving. These are code-defined UI behaviors; the UI does not establish interpretation accuracy on arbitrary production flyers ([InterpretationReviewViews.swift](../../Sources/DateSnap/Views/InterpretationReviewViews.swift#L1-L211), [EventReviewViewModel+Interpretation.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel+Interpretation.swift#L1-L141)).

### Batch Review

Batch scans are sequential and each image has an independent pending/scanning/found/no-dates/already-saved/failed state. One source failure does not stop later scans. Thumbnails are downsampled to at most 1280 points on the longest edge. Batch review creates a separate editable review model per candidate, supports expand/collapse, edit title/location, per-event destinations/alert offsets, per-event discard/save, and Save All. Failed events remain actionable for retry; succeeded/partial commits count as saved; skipped sources show a reason ([BatchScanViewModel.swift](../../Sources/DateSnap/ViewModels/BatchScanViewModel.swift#L20-L89), [BatchScanViewModel.swift](../../Sources/DateSnap/ViewModels/BatchScanViewModel.swift#L92-L207), [BatchScanViewModel.swift](../../Sources/DateSnap/ViewModels/BatchScanViewModel.swift#L273-L345), [BatchReviewView.swift](../../Sources/DateSnap/Views/BatchReviewView.swift#L24-L78), [BatchReviewView.swift](../../Sources/DateSnap/Views/BatchReviewView.swift#L137-L264)).

There is no configured maximum selection count in the inspected picker/batch code. Premium marketing copy mentions “up to 10” queued flyers, whereas the native Photos picker code does not enforce that limit ([PlusPaywallView.swift](../../Sources/DateSnap/Views/PlusPaywallView.swift#L130-L150), [HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L489-L500)).

### No Dates Found

Shows a preview/Inspect sheet for the last image, OCR fragment count and on-device disclosure, explanatory diagnostics, an expandable raw OCR list with Copy Raw OCR, “Create Event Manually from Image,” scan-another, and discard/return. Manual creation uses the first OCR fragment (or blank title), tomorrow at 7:00 PM, and a fallback end; it inserts a candidate and opens Event Review. A SwiftData save error toasts and leaves the screen in place ([NoDatesFoundView.swift](../../Sources/DateSnap/Views/NoDatesFoundView.swift#L5-L30), [NoDatesFoundView.swift](../../Sources/DateSnap/Views/NoDatesFoundView.swift#L147-L325), [NoDatesFoundView.swift](../../Sources/DateSnap/Views/NoDatesFoundView.swift#L329-L354)).

### Saved Event Detail

Re-reads the live candidate by ID with the opening snapshot as fallback, displays Calendar/Reminders presence, alert offsets and extracted context, and offers Open in Calendar (`calshow:`), Directions, Edit, Alerts, and ShareLink. Share text contains title/date/time, location and notes ([SavedEventDetailView.swift](../../Sources/DateSnap/Views/SavedEventDetailView.swift#L4-L37), [SavedEventDetailView.swift](../../Sources/DateSnap/Views/SavedEventDetailView.swift#L39-L250), [SavedEventDetailView.swift](../../Sources/DateSnap/Views/SavedEventDetailView.swift#L410-L493)). The Calendar button is disabled unless a saved Calendar external identifier exists. Schedule changes route through `SavedEventActions.rescheduleAlerts`, which updates existing Calendar alarms, Reminder offsets and local notifications for a saved event; it records partial external failures ([ReminderScheduleEditorView.swift](../../Sources/DateSnap/Views/ReminderScheduleEditorView.swift#L459-L490), [SavedEventActions.swift](../../Sources/DateSnap/Services/SavedEventActions.swift#L43-L103)).

### History & Archive

Saved/Draft/Archived chips include counts. Search checks title, venue, address, notes, date string and target calendar. Smart filters are Upcoming, RSVP Due, Repeats, and Possible Duplicates; duplicate clustering is Premium-gated. Cards open Drafts in Review and other states in Detail. Context/swipe/accessibility actions archive/restore, edit saved events, or request deletion. Delete offers DateSnap-only removal or, if Calendar identifier exists, Calendar & Reminders removal. Archiving removes pending local notifications. When restored, records with Calendar IDs return to Saved, otherwise Draft. Mutation success, partial and failure are surfaced via toast ([HistoryArchiveView.swift](../../Sources/DateSnap/Views/HistoryArchiveView.swift#L16-L87), [HistoryArchiveView.swift](../../Sources/DateSnap/Views/HistoryArchiveView.swift#L89-L238), [HistoryArchiveView.swift](../../Sources/DateSnap/Views/HistoryArchiveView.swift#L240-L444), [SavedEventActions.swift](../../Sources/DateSnap/Services/SavedEventActions.swift#L106-L179)).

### Reminder Schedule Editor

Offers Default (1 day, 2 hours), Travel Heavy (2 days, 3 hours, 45 minutes), Day-of Only (2 hours) and Custom. Each offset is selected from a finite catalog; duplicates are disabled; users can remove/add offsets, up to three, and see a computed fire time (past dates are labeled “passed”). Save sorts offsets and calls a supplied callback; success dismisses, partial/failure stays and displays an alert; Reset to Default and Discard Changes are available. The visible “Channel” strip is fixed text (“Calendar · Reminders · Alert”), not a selectable channel control. All-day offsets resolve to 9:00 AM local time on the offset day ([ReminderScheduleEditorView.swift](../../Sources/DateSnap/Views/ReminderScheduleEditorView.swift#L5-L34), [ReminderScheduleEditorView.swift](../../Sources/DateSnap/Views/ReminderScheduleEditorView.swift#L100-L290), [ReminderScheduleEditorView.swift](../../Sources/DateSnap/Views/ReminderScheduleEditorView.swift#L290-L457), [ReminderService.swift](../../Sources/DateSnap/Services/ReminderService.swift#L5-L62)).

The notification service ignores already-past notification trigger dates, but Calendar/Reminders scheduling is a distinct EventKit write path; source code alone does not establish how each OS destination presents a past alarm ([NotificationService.swift](../../Sources/DateSnap/Services/NotificationService.swift#L99-L157), [CalendarService.swift](../../Sources/DateSnap/Services/CalendarService.swift#L103-L145), [ReminderService.swift](../../Sources/DateSnap/Services/ReminderService.swift#L131-L177)).

### Permission recovery screens

- **Calendar denial** explains Calendar write failure, lists supported fallback capabilities and links to iOS Settings; Not Now dismisses and leaves review in place ([CalendarPermissionDeniedView.swift](../../Sources/DateSnap/Views/CalendarPermissionDeniedView.swift#L4-L31), [CalendarPermissionDeniedView.swift](../../Sources/DateSnap/Views/CalendarPermissionDeniedView.swift#L129-L220)). Calendar creation requires authorized/full access and a writable target; update recreates a missing event. Existing Calendar events are not fetched/listed as part of the inspected service ([CalendarService.swift](../../Sources/DateSnap/Services/CalendarService.swift#L58-L100), [CalendarService.swift](../../Sources/DateSnap/Services/CalendarService.swift#L103-L178)).
- **Notification denial** offers Enable in Settings or continue with Calendar alarms. The dedicated screen exists, but the single-event commit path can save Calendar/Reminders and report notification failure as partial rather than forcing this screen ([NotificationPermissionDeniedView.swift](../../Sources/DateSnap/Views/NotificationPermissionDeniedView.swift#L4-L35), [NotificationPermissionDeniedView.swift](../../Sources/DateSnap/Views/NotificationPermissionDeniedView.swift#L146-L190), [EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L422-L476)).
- `Info.plist` contains usage descriptions for Photos, Calendar and Reminders (including full-access keys); notification permission is requested by `UNUserNotificationCenter` at schedule time. `DateSnap.entitlements` is empty except for a comment that no remote push/iCloud entitlement is required ([Info.plist](../../Info.plist#L27-L36), [DateSnap.entitlements](../../DateSnap.entitlements#L1-L7), [NotificationService.swift](../../Sources/DateSnap/Services/NotificationService.swift#L29-L61)).

### Settings Hub and Settings subviews

- **Settings Hub:** profile/tier, subscription management, Enhanced Interpretation route, Reminder Preview, default calendar selection, privacy controls, restore purchases, help and feedback. Restore reports either a toast or an alert ([SettingsHubView.swift](../../Sources/DateSnap/Views/SettingsHubView.swift#L5-L35), [SettingsHubView.swift](../../Sources/DateSnap/Views/SettingsHubView.swift#L75-L180), [SettingsHubView.swift](../../Sources/DateSnap/Views/SettingsHubView.swift#L182-L302)).

### Plus/Premium paywalls and purchase edge cases

The app defines Starter/Plus/Premium tiers. Plus-gated convenience features are automatic screenshot surfacing and likely-event triage. Premium gates Files/PDF import, duplicate clusters and advanced reminder plans. Feature policy denies access while entitlement is checking, unverified or unavailable ([SubscriptionService.swift](../../Sources/DateSnap/Services/SubscriptionService.swift#L1-L36), [FeatureEntitlements.swift](../../Sources/DateSnap/Services/Advisors/FeatureEntitlements.swift#L1-L50), [FeatureEntitlements.swift](../../Sources/DateSnap/Services/Advisors/FeatureEntitlements.swift#L110-L164)). Basic scan, interpretation and manual review are described by the entitlement code as correctness features, not paid gates.

Both paywalls choose annual by default, fetch localized StoreKit pricing, show monthly equivalent/free-trial details where available, disable purchase without a loaded product or during loading/purchase, offer monthly/annual selection, purchase, restore, terms and privacy. Cancellation returns without an error message, pending purchase produces a pending-approval message, unavailable products show “Price unavailable,” and purchase/restore failures appear in an alert ([PurchaseViewModel.swift](../../Sources/DateSnap/ViewModels/PurchaseViewModel.swift#L7-L115), [PlusPaywallView.swift](../../Sources/DateSnap/Views/PlusPaywallView.swift#L280-L370), [PremiumPaywallView.swift](../../Sources/DateSnap/Views/PremiumPaywallView.swift#L270-L375)). StoreKit product IDs are four exact Plus/Premium monthly/annual identifiers; transaction verification and entitlement resolution fail closed ([SubscriptionService.swift](../../Sources/DateSnap/Services/SubscriptionService.swift#L46-L196), [SubscriptionEntitlementResolver.swift](../../Sources/DateSnap/Services/SubscriptionEntitlementResolver.swift#L1-L75)).

Paywall benefit/marketing strings also mention features such as geofence alerts, custom calendar color tagging, “ICS bidirectional sync,” Dropbox import and recurring scan routines. Those particular features are **not established by the audited flow**: current importer accepts local PDF/image, Calendar/Reminders integrations use EventKit, and no geofence/ICS/cloud-import implementation was identified in the inventoried app paths ([PremiumPaywallView.swift](../../Sources/DateSnap/Views/PremiumPaywallView.swift#L115-L155), [ManagePlanView.swift](../../Sources/DateSnap/Views/ManagePlanView.swift#L205-L238), [ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L106-L149)).

## 4. Services, models, persistence and permissions

### Scan/extraction services

- `PhotoLibraryService` requests read/write access, fetches from the Screenshots smart album, disables network access when fetching an image, and emits change events while an observer is registered ([PhotoLibraryService.swift](../../Sources/DateSnap/Services/PhotoLibraryService.swift#L1-L70), [PhotoLibraryService.swift](../../Sources/DateSnap/Services/PhotoLibraryService.swift#L79-L147)).
- `OCRService` uses Vision `VNRecognizeTextRequest` at `.accurate`, with language correction and automatic language detection. It returns line text, confidence and geometry ordered top-to-bottom; missing text, invalid image and low confidence are errors ([OCRService.swift](../../Sources/DateSnap/Services/OCRService.swift#L1-L67), [OCRService.swift](../../Sources/DateSnap/Services/OCRService.swift#L74-L140)).
- `EventExtractionCore` is deterministic and includes false-positive filtering, OCR line/block segmentation, date/title/location/contact/time-zone/dedupe inference; `RuleBasedEventAnalyzer` attaches evidence, temporal roles, recurrence/actions/category and quality report ([EventExtractionService.swift](../../Sources/DateSnap/Services/EventExtractionService.swift#L169-L238), [RuleBasedEventAnalyzer.swift](../../Sources/DateSnap/Services/Intelligence/RuleBasedEventAnalyzer.swift#L8-L97)).
- OCR retry uses a contrast-enhanced image if initial text is missing or quality is low, and keeps the retry when confidence/scan-worthiness improves ([ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L301-L324)).

### Calendar, Reminders, notifications

- `CalendarService` requests full event access, chooses the selected/system/first writable calendar, creates/updates/deletes EventKit events, and writes candidate values, notes, optional recurrence and alarms. Missing external event on update is recreated ([CalendarService.swift](../../Sources/DateSnap/Services/CalendarService.swift#L58-L100), [CalendarService.swift](../../Sources/DateSnap/Services/CalendarService.swift#L103-L235)).
- `ReminderService` creates/updates/deletes an `EKReminder`, with up to three alarms, list selection, event context and a separate deadline reminder ([ReminderService.swift](../../Sources/DateSnap/Services/ReminderService.swift#L64-L130), [ReminderService.swift](../../Sources/DateSnap/Services/ReminderService.swift#L131-L278)).
- `NotificationService` requests local alert/sound/badge permission on scheduling, schedules future non-repeating calendar triggers, ignores past triggers, validates optional web links, removes pending IDs and routes notification actions through `DeepLinkInbox` ([NotificationService.swift](../../Sources/DateSnap/Services/NotificationService.swift#L29-L98), [NotificationService.swift](../../Sources/DateSnap/Services/NotificationService.swift#L99-L237)).
- Event commit order is Calendar, then best-effort Reminders/deadline reminder/local notifications, then SwiftData. Calendar denial fails the commit; other destination problems can produce a partial saved event. If the final local save fails, the error explicitly notes that external writes may already have happened ([EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L315-L422)).

### SwiftData records and retention boundary

The schema includes a singleton-like `UserSettings` model, `ScannedAsset` (asset ID, scan date, raw OCR, confidence/count), `EventCandidate` (event fields, raw text snippet, confidence/ambiguity/dedupe/interpretation metadata), versioned `InterpretationRecord` payloads, and `SavedEvent` (Calendar/Reminder/notification IDs, status, alert offsets and optional deadline-reminder ID) ([SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L48-L89), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L90-L123), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L124-L224), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L225-L290), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L291-L353)).

**Retention qualification:** `clearScanCache()` clears `ScannedAsset.rawOcrText` and deletes `InterpretationRecord`s, but does not clear `EventCandidate.rawTextSnippet`; those candidate snippets remain available to the review/detail model (and Calendar notes on save). Thus the Settings label “Clear Scan Text” is broader than the fields this method clears. `eraseAllLocalData()` deletes local SwiftData records and cancels recorded pending local notification IDs, while its explicit contract is to keep Calendar and Reminders entries already written; it does not enumerate/remove those external entries. The inspected reset code also does not remove standalone RSVP deadline reminders by their stored IDs. Source images kept in `AppState` are in-memory references; this schema does not store image binary data ([SavedEventActions.swift](../../Sources/DateSnap/Services/SavedEventActions.swift#L181-L230), [PrivacyCenterView.swift](../../Sources/DateSnap/Views/PrivacyCenterView.swift#L60-L108), [AppState.swift](../../Sources/DateSnap/Models/AppState.swift#L78-L90)).

Privacy copy states OCR/image handling is on-device; code evidence supports local Vision/OCR, local model processing and Photos image requests with network access disabled. These mechanisms do not establish how iOS/iCloud syncs the user’s selected Calendar/Reminders accounts or where the OS stores those records ([PrivacyCenterView.swift](../../Sources/DateSnap/Views/PrivacyCenterView.swift#L41-L58), [OCRService.swift](../../Sources/DateSnap/Services/OCRService.swift#L74-L140), [PhotoLibraryService.swift](../../Sources/DateSnap/Services/PhotoLibraryService.swift#L79-L111), [EventUnderstandingPipeline.swift](../../Sources/DateSnap/Services/Intelligence/EventUnderstandingPipeline.swift#L1-L20)).

## 6. Evidence limits and code-vs-copy observations

1. A `PHPhotoLibraryChangeObserver` and reload path are present, but no background task registration/always-on service is established by the inspected app source. Plus surfaced screenshots still require the user to select one to scan ([PhotoLibraryService.swift](../../Sources/DateSnap/Services/PhotoLibraryService.swift#L115-L147), [HomeViewModel.swift](../../Sources/DateSnap/ViewModels/HomeViewModel.swift#L164-L181), [HomeEmptyStateView.swift](../../Sources/DateSnap/Views/HomeEmptyStateView.swift#L555-L630)).

3. “Reminder Preview” is a preview-only date control, not a persisted defaults editor ([ReminderSettingsView.swift](../../Sources/DateSnap/Views/ReminderSettingsView.swift#L3-L58)).
4. “Clear Scan Text” leaves candidate raw-text snippets intact; reset intentionally leaves EventKit Calendar/Reminders entries and may leave a separately created deadline reminder ([SavedEventActions.swift](../../Sources/DateSnap/Services/SavedEventActions.swift#L181-L230), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L124-L165), [SwiftDataEntities.swift](../../Sources/DateSnap/Persistence/SwiftDataEntities.swift#L306-L353)).
5. The notification-denial screen exists, but the normal save path can keep the user in the event flow and toast that local alerts were skipped rather than routing to it ([EventReviewViewModel.swift](../../Sources/DateSnap/ViewModels/EventReviewViewModel.swift#L422-L476), [EventReviewEditView.swift](../../Sources/DateSnap/Views/EventReviewEditView.swift#L846-L862)).
6. Marketing copy in paywalls/manage-plan should not be read as implementation proof for features whose implementation was not found in the app paths audited (e.g. geofencing, ICS bidirectional sync, Dropbox/cloud-drive import, recurring scan routines) ([PremiumPaywallView.swift](../../Sources/DateSnap/Views/PremiumPaywallView.swift#L115-L155), [ManagePlanView.swift](../../Sources/DateSnap/Views/ManagePlanView.swift#L205-L238), [ScanViewModel.swift](../../Sources/DateSnap/ViewModels/ScanViewModel.swift#L106-L149)).

All observations are bounded to inspected source and test files as of 2026-10-09. Statements about what the code does not establish are deliberately not recast as runtime failures or product guarantees.
